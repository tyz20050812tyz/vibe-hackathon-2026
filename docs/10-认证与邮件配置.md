# 认证与邮件配置

认证页面仅调用本项目的 `/api/auth/*` 接口。Supabase Auth 负责账户、密码与邮箱验证，浏览器会话由 HTTP-only Cookie 保存；`profiles` 和 `saved_resources` 继续使用既有 migration 中的 RLS 策略。

## QQ 邮箱 SMTP

QQ 邮箱 SMTP 用于当前 Demo 的验证邮件。应用服务端调用 Supabase Admin `generateLink` 签发确认链接，再由 Nodemailer 连接 QQ SMTP 发送，因此不需要 Supabase Custom SMTP。

| 设置 | 值 |
| --- | --- |
| Host | `smtp.qq.com` |
| Port | `465` |
| Encryption | SSL/TLS |
| Username | 用于发送邮件的完整 QQ 邮箱地址 |
| Password | QQ 邮箱生成的 SMTP 授权码，不是 QQ 登录密码 |
| Sender name | 书外之遇 |

将对应值写入服务器环境变量 `SMTP_HOST`、`SMTP_PORT`、`SMTP_USER`、`SMTP_PASS` 和 `SMTP_FROM`。本地参考 `.env.example`，部署时在 Vercel 环境变量中设置；不使用 `NEXT_PUBLIC_` 前缀。配置前在 QQ 邮箱设置中开启 SMTP 服务并生成授权码。

Supabase 的 Redirect URLs 必须包含 `{NEXT_PUBLIC_SITE_URL}/auth/confirmed` 所属的域名，例如本地 `http://localhost:3000/auth/confirmed` 和部署地址 `https://your-domain.com/auth/confirmed`。`Site URL` 也应设为部署的主域名。

## 发布前检查

- 从 QQ 邮箱注册，确认收到验证邮件并能完成验证。
- 验证后登录，再收藏、刷新、退出、重新登录，确认书架仍正确。
- 确认 `SUPABASE_SERVICE_ROLE_KEY`、QQ 授权码、验证链接和任何 access token 不出现在浏览器、日志或 Git 中。
- 若验证邮件频率或到达率成为问题，迁移到专用事务邮件服务；QQ 邮箱更适合低量 Demo，不适合作为高并发生产邮件通道。
