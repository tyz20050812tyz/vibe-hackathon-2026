## 3. 命名与序列化规则

| 场景 | 规则 | 示例 |
| --- | --- | --- |
| PostgreSQL 表和字段 | `snake_case` | `saved_resources`, `published_year` |
| TypeScript 与 API JSON | `camelCase` | `savedResources`, `publishedYear` |
| URL 资源标识 | 小写 kebab-case slug | `the-library-of-babel` |
| 数据库主键 | UUID | `id` |
| 时间字段 | 数据库存 `timestamptz`，API 返回 ISO 8601 字符串 | `2026-08-21T09:30:00.000Z` |
| 空值 | 不存在或未知的数据使用 `null`，不使用空字符串 | `coverUrl: null` |
| 枚举 | 只用预定义小写字符串，不临时新增 | `availability: "online"` |

数据库字段到 API 字段的映射由 `lib/services/` 负责，页面不得处理 `snake_case`。

## 4. 通用 API 规则

所有接口使用 `lib/types/api.ts` 的统一响应：

```ts
type ApiSuccess<T> = {
  data: T;
  requestId: string;
};

type ApiFailure = {
  data: null;
  error: { code: ApiErrorCode; message: string };
  requestId: string;
};
```

| 情况 | HTTP | 错误码 |
| --- | --- | --- |
| 参数不合法 | 400 | `VALIDATION_ERROR` 或 `INVALID_JSON` |
| 未登录 | 401 | `UNAUTHORIZED` |
| 无权限 | 403 | `FORBIDDEN` |
| 资源不存在 | 404 | `RESOURCE_NOT_FOUND` |
| 重复收藏 | 409 | `ALREADY_SAVED` |
| 服务配置/外部服务失败 | 503 | `CONFIGURATION_ERROR` 或 `SUPABASE_UNAVAILABLE` |
| 其他服务端异常 | 500 | `INTERNAL_ERROR` |

前端不解析 Supabase 原始错误，也不通过错误英文文本判断业务状态。

## 6. 接口标准

| 接口 | 参数 / Body | 成功返回 |
| --- | --- | --- |
| `GET /api/resources` | `q?`, `tag?`, 重复 `language`/`type`/`availability`、`yearFrom?`、`yearTo?`、`sort?`、`limit?` | `SearchResourcesData` |
| `GET /api/resources/[slug]` | path `slug` | `GetResourceData` |
| `GET /api/reader-profile` | Bearer token | `ReadingProfileData` |
| `PUT /api/reader-profile` | `{ interestTagIds, explorationLevel, favoriteBooks?, consent: true }` | `ReadingProfileData` |
| `DELETE /api/reader-profile` | Bearer token | `{ cleared: true }` |
| `POST /api/discoveries` | `{ originResourceId, mode?, excludeResourceIds?, discoveryContext? }` | `DiscoverData` |
| `GET /api/saved-resources` | 无 | `SavedResource[]` |
| `POST /api/saved-resources` | `{ resourceId, note? }` | `SavedResource` |
| `DELETE /api/saved-resources/[resourceId]` | path `resourceId` | `{ resourceId }` |

每个 Route Handler 必须按以下顺序实现：解析输入 -> Zod 校验 -> 身份/归属检查 -> 调用 `lib/services/` -> 转换为 API 类型 -> 返回统一 JSON。

## 7. 权限规则

- 资源、标签和资源关系是公开可读数据；浏览器仍优先通过 Next.js API 读取，避免页面依赖数据库查询细节。
- `profiles` 和 `saved_resources` 必须开启 RLS。
- 用户只能读取、创建、删除自己的收藏；`saved_resources` 用 `(user_id, resource_id)` 主键防止重复收藏。
- `SUPABASE_SERVICE_ROLE_KEY` 仅限服务端 adapter 使用，绝不进入 Client Component、`NEXT_PUBLIC_` 变量、日志、文档样例或 Git。
- 任何写入用户数据的接口都必须在 API 层验证用户身份，即使数据库已经有 RLS。

## 11. 2026-08-26 AI 发现契约增补

本节是本项目 AI 发现模块对前述通用规则的冻结增补；模块详细方案见 [`docs/ai-discovery/方案设计.md`](ai-discovery/方案设计.md)。

### 11.1 认证与领域命名

- `/api/reader-profile` 的 GET、PUT、DELETE 统一要求 `Authorization: Bearer <access token>`；服务端只从 token 派生 `auth.uid()`，不接受 `userId`。公开的 `/api/resources` 个性化排序和 `/api/discoveries` 可选 Bearer；token 无效时回退公共目录。
- 阅读偏好领域统一命名为 `ReadingProfile`，不复用已有个人资料概念 `ReaderProfile`。GET 返回判别式 `{ status: "incomplete", preferences: null }` 或 `{ status: "complete", preferences: ReadingProfile }`。
- 画像写入只能调用 `replace_reader_profile`，清空只能调用 `clear_reader_profile`；两者为 `SECURITY DEFINER` 原子 RPC。`reader_profile_is_complete()` 是画像可用于个性化的唯一判定：存在已完成记录且恰有 3-8 个兴趣标签。三张 `reader_profile*` 表仅允许 authenticated 读取本人，禁止 authenticated/anon 直接写入。

### 11.2 搜索与筛选

`GET /api/resources` 支持 `q`、`tag`、重复键 `language`/`type`/`availability`、闭区间 `yearFrom`/`yearTo`、`sort=catalog|personalized` 和 `limit=1..50`。同字段多值为 OR，字段之间为 AND；重复值、未知键、非法枚举、年份反转均返回 `400 VALIDATION_ERROR`。`clearSearchFilters` 保留 `q`、`sort` 和 `limit`。

迁移顺序固定为 `20260821_create_library_foundation.sql`、`202608210001_add_resource_catalog_search.sql`、`202608260001_add_resource_languages.sql`、`202608260002_create_reader_profiles.sql`、`202608260003_create_resource_catalog_v2.sql`。最后一个 migration 删除旧四参数 `search_resource_catalog(text,text,text,integer)`（可重复执行），再创建 `search_resource_catalog_v2` 与仅 authenticated 可执行的 `search_resource_catalog_personalized_v2`，避免 RPC 同名重载。

### 11.3 发现与隐私

`POST /api/discoveries` 只从 `resource_relations` 选择候选；硬筛选先于画像排序，空候选返回 HTTP 200。带 `discoveryContext` 时使用服务端 AES-256-GCM、5 分钟过期 token，响应必须为 `Cache-Control: private, no-store` 和 `Referrer-Policy: same-origin`；日志只能记录 `present|invalid|expired`，不得记录 token、请求体或完整 URL。搜索资源卡由服务端签发 context 并传入详情链接。

新增错误码为 `INVALID_DISCOVERY_CONTEXT`（400）和 `RATE_LIMITED`（429）。`Resource`/`ResourceListItem` 必须包含 `languages`，列表项包含 `publishedYear`；搜索响应始终返回规范化 `appliedFilters`、实际 `appliedSort` 与 `personalization` 来源。
