# 第一阶段实施计划：资源目录与个人书架

> 目标：在加入 AI、知识地图和“意外发现”之前，先交付一个真正可使用的数字图书馆基础层。

## 1. 第一阶段完成后的样子

用户第一次进入产品时，可以：

```text
首页发现主题
-> 搜索 “AI” 或 “创造力”
-> 按主题筛选资源
-> 打开一本书/论文详情
-> 登录后收藏到个人书架
-> 刷新页面后仍能在个人书架中找到它
```

这一阶段不做 AI 问答和知识地图，但数据结构会为下一阶段的“带我偏离一点”预留关系数据。

## 2. 范围与验收标准

### P0：必须完成

| 能力 | 用户可见结果 | 验收标准 |
| --- | --- | --- |
| 首页发现 | 看到精选资源与热门主题 | 点击主题可进入已带筛选条件的搜索结果 |
| 关键词搜索 | 能按标题、作者、摘要搜索 | 输入 `AI` 可返回至少 3 条匹配资源 |
| 标签筛选 | 能按一个主题缩小结果 | 选中标签后 URL 和结果同步变化 |
| 资源详情 | 可理解一项资源是什么、在哪里、为何值得读 | 有封面、作者、摘要、标签、馆藏状态与位置 |
| 登录与收藏 | 能收藏、取消收藏并在个人书架查看 | 刷新后收藏状态仍存在，不能收藏重复项 |
| 错误与空态 | 网络或无结果时不白屏 | 无结果、未登录、接口失败均有明确提示 |

### P1：时间允许时完成

- 资源排序：最新、最受欢迎、编辑精选；
- 收藏时附一条个人笔记；
- 书架中的“最近浏览”；
- 资源详情里的“相关主题”预览；
- 搜索建议与键盘快捷提交。

### 第一阶段明确不做

- 借阅、归还、图书馆管理员系统；
- 实时馆藏、座位、门禁或预约；
- 用户关系、消息、匹配；
- LLM 调用、动态知识图谱；
- 全量图书馆数据爬取。

## 3. 先共同定下来的产品规则

### 3.1 资源数据策略

采用**人工精选种子数据**，而不是先接入难以控制的真实馆藏系统。

第一版准备 80 条左右资源：

| 类型 | 建议数量 | 内容 |
| --- | --- | --- |
| `book` | 40 | 图书，带作者、馆藏位置、封面与摘要 |
| `paper` | 20 | 论文或研究报告，带作者、年份、摘要与外部链接 |
| `talk` | 10 | 讲座、课程或展览活动 |
| `collection` | 10 | 编辑策展专题，例如“技术与人文”“偶遇的城市” |

主题覆盖至少六个方向：人工智能、心理学、文学、设计、城市、社会学。每条资源至少有 2 个标签；重点资源可有 3 到 5 个标签。

**不伪造真实借阅状态。** `availability` 只表示 Demo 中的“可馆内阅读”“可在线阅读”“馆藏待查”等展示状态，并在文案中清楚说明。

### 3.2 三条测试故事

两人先共同选定以下三条故事，用于种子数据、页面验收和最终 Demo：

1. `AI 与创造力`：技术用户从 AI 资源进入认知心理学和生成艺术。
2. `城市与记忆`：用户从城市空间进入文学、摄影和社会学。
3. `偶然阅读`：用户从一部小说进入图书馆学、哲学或设计。

第一阶段只要确保用户能搜到这三条故事中的起点资源、查看详情并收藏。第二阶段再补它们的意外分叉。

## 4. 开发顺序

### 里程碑 A：可搜索的公共资源目录

```text
Supabase 资源表和种子数据
-> GET /api/resources
-> 首页与搜索页 Mock
-> 替换为真实 API
-> GET /api/resources/[slug]
-> 资源详情页
```

**完成定义：** 不登录也能完成搜索和资源详情浏览。

### 里程碑 B：有沉淀的个人书架

```text
Supabase Auth
-> profiles / saved_resources 表与 RLS
-> 收藏与取消收藏 API
-> 详情页收藏交互
-> /library 个人书架
```

**完成定义：** 登录用户能保存资源，刷新与重新登录后书架仍正确。

不要同时开启两个里程碑。A 的搜索和详情接口稳定后，才开始 B。

## 5. 两人分工

### 5.1 共同工作：开始前 60 分钟

| 事项 | 产出 | 完成标准 |
| --- | --- | --- |
| 定义用户与故事 | 三条测试故事 | 每条有搜索词、起点资源、详情卖点 |
| 核对资源字段 | 数据契约规范与共享类型 | 前后端确认不新增临时字段 |
| 定义页面路线 | 首页、搜索、详情、书架线框 | 每页只保留 P0 内容 |
| 定义数据来源 | 种子资源表 | 明确谁收集、谁录入、何时完成 |
| 核对接口 | 数据契约规范中的既定接口 | 双方确认按既定参数、返回结构和错误状态实现 |

数据和 API 的唯一规则是 `docs/09-数据契约规范.md`；双方不得各自发明字段、接口或返回格式。

### 5.2 佟雨泽：PM1 + 前端 + 用户路径测试

| 时段 | 工作 | 交付物 |
| --- | --- | --- |
| A1 | 信息架构与视觉方向 | 页面流程图、P0 页面清单、资源卡片样式 |
| A2 | 首页与搜索 Mock | `app/page.tsx`、`app/search/page.tsx`、资源卡片与筛选组件 |
| A3 | 详情页 Mock | `app/resources/[slug]/page.tsx`、详情头部、标签、馆藏信息、收藏按钮 |
| A4 | 联调 API | 用共享类型替换 Mock 数据，补加载/空态/失败态 |
| B1 | 身份与收藏 UI | 登录入口、收藏状态、未登录提示 |
| B2 | 个人书架 | `app/library/page.tsx`、收藏列表、取消收藏、空态 |
| B3 | E2E 冒烟 | 搜索、详情、收藏、刷新、取消收藏的验收清单 |

前端约束：

- 所有资源页面只依赖 `lib/types/resources.ts` 中导出的类型；
- API 未完成前可以使用 `lib/mocks/resources.ts`，但字段形状必须与正式接口一致；
- 每个请求都必须有 loading、empty、error、success 四种状态；
- 不在页面里直接访问 Supabase 或读取环境变量；
- 收藏按钮必须防重复点击，未登录时展示登录引导，不假装收藏成功。

### 5.3 杨思涵：PM2 + 后端 + 数据与接口测试

| 时段 | 工作 | 交付物 |
| --- | --- | --- |
| A1 | 数据方案与迁移 | `resources/tags/resource_tags/resource_relations` SQL、索引、种子数据脚本 |
| A2 | 资源目录模块 | `lib/services/resource-catalog.ts`，封装搜索、详情和标签查询 |
| A3 | 只读接口 | 按数据契约实现资源搜索与详情接口，含 Zod 校验和统一错误格式 |
| A4 | 接口自测与联调 | curl/API 验证、参数边界、Vercel Preview 验证 |
| B1 | Supabase Auth 与 Profile | Auth 配置、`profiles` 表、首次登录资料策略 |
| B2 | 收藏模块 | `saved_resources` 迁移、RLS、收藏/取消/列表 service 与 API |
| B3 | 后端验收 | 越权检查、重复收藏检查、失败日志、部署环境检查 |

后端约束：

- `app/api/` 只解析请求、校验输入、调用 service、映射 HTTP 错误；
- Supabase 查询写入 `lib/services/`，客户端创建集中在 `lib/supabase/`；
- 不向浏览器返回 service-role key、Supabase 原始错误或内部 SQL 信息；
- 对用户数据使用 Supabase Auth 与 RLS；不可用 service-role key 绕过用户归属；
- 所有迁移均保存到 `supabase/migrations/`，种子数据保存到 `supabase/seed/`。

```text

  search/page.tsx                  # 佟雨泽：搜索页
  resources/[slug]/page.tsx        # 佟雨泽：详情页
  library/page.tsx                 # 佟雨泽：个人书架
  api/resources/                   # 杨思涵：资源读接口
  api/saved-resources/             # 杨思涵：收藏接口
components/resources/              # 佟雨泽：资源卡、筛选、详情组件
lib/types/resources.ts             # 共同维护：资源契约
lib/services/resource-catalog.ts   # 杨思涵：资源查询模块
lib/services/personal-library.ts   # 杨思涵：收藏模块

lib/mocks/resources.ts             # 佟雨泽：与契约同形状的临时数据
supabase/migrations/               # 杨思涵：每次数据库变更
supabase/seed/                     # 共同维护：资源种子数据
```

## 7. 开发与通信要求

数据字段、API 路径与格式、数据库、权限、契约变更流程的唯一规范是 [数据契约规范](./09-数据契约规范.md)。双方每次开发、联调或让 AI 编码前，都必须先阅读该文件和其指向的 TypeScript 类型、Zod schema、migration；不得在本计划或页面代码中另立规则。

本计划仅固定前端页面范围：`/`、`/search`、`/resources/[slug]`、`/library`。页面路径是用户入口；API 路径及请求/响应细节以数据契约规范为准，它们不要求一一同名。页面路径或数据契约任何一方需要变更时，先按规范提出契约变更，双方确认后再实现。

前端可以按契约先做 Mock；后端按同一契约实现 migration、service 和 API；联调时前端只替换数据来源，不重写数据形状。

## 8. 具体推进日程

### 第 0 天 / 启动会（1 小时）

1. 两人一起确定产品名、视觉关键词和三条测试故事。
2. 共同核对数据契约规范、共享类型与页面范围，不新增临时字段。
3. 选出首批 20 条资源作为开发数据，剩余数据后补。
4. 确认 `slug` 页面路径与现有数据契约一致。

**输出：** 一份已确认的数据契约检查记录；双方均以该规范为唯一字段和接口来源。

### 第 1 天 / 资源闭环（6-8 小时）

| 时段 | 佟雨泽 | 杨思涵 | 会合点 |
| --- | --- | --- | --- |
| 0-2h | 首页、资源卡和搜索页 Mock | 迁移、20 条种子、资源查询模块 | 确认真实返回字段 |
| 2-4h | 搜索筛选与 URL 状态 | 按契约实现搜索接口与参数校验 | 前端改接真实搜索 API |
| 4-6h | 详情页与状态设计 | 按契约实现详情接口与相关资源 | 搜索 -> 详情全路径联调 |
| 6-8h | 移动端、空态、错误态 | 接口边界与 Preview 验证 | Vercel Preview 冒烟测试 |

## 9. 每天的同步与 Git 规则

### 开始前 10 分钟

- 说清各自今天要交付的路由、接口或迁移；
- 若改 `lib/types/resources.ts`，先一起确认再编码；
- 每项任务写一个可验收结果，例如“搜索 `AI` 返回三条资源”。

### 中途 10 分钟

- 对齐 API 是否已可用；
- 若未可用，前端继续按 Mock 类型开发，不临时改字段；
- 发现字段缺失时，先修改契约并告知对方。

### 收尾 20 分钟

- 各自跑 `npm run lint`、`npm run build`；
- 通过 PR 合并，不直接推 `main`；
- 在 Vercel Preview 走一次完整主路径；
- 把阻塞项写到下一天任务中。

推荐分支：

```text
feat/resource-schema-and-seed       # 杨思涵
feat/resource-search-ui             # 佟雨泽
feat/resource-catalog-api           # 杨思涵
feat/resource-detail-page           # 佟雨泽
feat/personal-library               # 两人拆成前后端小 PR
```

## 10. 第一阶段最终验收清单

- [ ] 首页能显示精选资源与热门主题。
- [ ] 搜索 `AI` 返回预期资源；无结果显示空态。
- [ ] 标签筛选可以与关键词共同使用。
- [ ] 资源详情 URL 使用 `slug`，刷新后仍可打开。
- [ ] 资源详情包含摘要、标签、可读状态和位置。
- [ ] 未登录用户能浏览，但收藏时会收到清晰引导。
- [ ] 登录用户可收藏、取消收藏，刷新后书架仍正确。
- [ ] 用户无法读取或删除他人的收藏。
- [ ] 所有 P0 页面存在 loading、empty、error、success 状态。
- [ ] `npm run lint`、`npm run build`、Vercel Preview 都通过。

## 11. 进入第二阶段的门槛

只有在以下条件全部满足后，才开始做 AI 与意外发现：

1. 资源搜索、详情、收藏、书架的完整路径已在 Production 或 Preview 稳定跑通。
2. 三条测试故事的起点资源均可搜索、打开和收藏。
3. `resources`、`tags`、`resource_tags`、`resource_relations` 已有稳定种子数据。
4. 两人对 `Resource` 类型与错误格式没有未解决分歧。

达到门槛后，资源详情页的收藏按钮旁边新增“带我偏离一点”，即可自然进入第二阶段。
