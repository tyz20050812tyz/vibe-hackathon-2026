# AI Discovery P0 发布收敛计划

## 1. 目标与边界

本计划以 [方案设计.md](方案设计.md) 为唯一规格，目标是让“模板叙述模式”的资源发现功能达到 P0 发布门禁，而不是在本轮提前开启 DeepSeek。

当前已知状态：20 条公开可展示资源中，只有 3 个起点具有出向关系；`the-creative-act` 有 5 条、`the-image-of-the-city` 有 6 条、`the-library-of-babel` 有 6 条。其余 17 个起点为 0 条。8 个精选资源必须达到每个至少 3 条且至少覆盖两种关系类型，9 个普通资源必须达到每个至少 1 条。因此，本轮最小需新增 33 条唯一 `(source, target, relation_type)` 关系。

本轮 P0 包含：关系数据补齐、可重复执行的 seed 和覆盖审计、迁移/RLS/发现 API 的可执行验证、前端 E2E 冒烟、Preview 发布验收。

本轮不包含：开启 DeepSeek、反馈学习、模型文案持久化、自动推断标签和向量检索。DeepSeek 资源控制仍需在 P1 单独实现和验证，P0 继续固定返回 `narrationSource: "template"`。

## 2. 责任与协作规则

| 角色 | 负责人 | 负责内容 | 不负责内容 |
| --- | --- | --- | --- |
| 前端 | 佟雨泽 | E2E 运行环境、浏览器交互测试、推荐来源呈现、前端失败态和联调验收 | 在浏览器创建/解密 context、客户端个性化排序、直接读写画像表、DeepSeek 调用 |
| 后端 | 杨思涵 | 关系 seed/审计、迁移修复、Supabase 部署、RLS/RPC/Route/服务测试、context 校验与日志审计 | 页面状态、筛选控件和客户端交互 |
| 共同 | 佟雨泽、杨思涵 | 每条关系的内容确认、共享类型/错误码变更、测试 fixture、Preview 验收与上线判定 | 未经双方确认改变既定 API 语义 |

关系内容采用“人工策展确认，后端机械落库”的方式：不由 AI 自动补全。每条记录在进入 SQL 前必须有策展记录：`sourceSlug -> targetSlug + relationType + explanation + strength + 审核人`。后端只校验并转换，不改变关系类型或解释含义。

## 3. 执行顺序与依赖

```text
人工确认 33 条关系
        |
        v
杨：v3 seed + 覆盖审计 + 真实 Supabase 测试
        |
        +------> 佟：Playwright/E2E 基础设施与 UI 来源标识
        |                     |
        +---------------------+
                              v
                       Preview 联调与验收
                              |
                              v
                         P0 发布判定
```

前端 E2E 基础设施可以与后端 seed 编写并行；依赖真实关系数据的发现断言，必须在 Preview seed 完成后执行。迁移/RLS 测试必须先于生产部署完成。

## 6. 发布门禁

以下任一项未通过，则 P0 不发布：

1. `resources-v3-relation-coverage.sql` 可重复执行，且覆盖审计表明 20/20 资源合格、8/8 精选入口合格。
2. 迁移顺序在 Preview 数据库通过；旧 RPC 已删除、无遗留 grant 或重载。
3. 两用户 RLS、受控 RPC 与 REST 直写拒绝为真实数据库测试结果，而不是 SQL 字符串断言。
4. 新发现 API 的关键分支和前端三条核心 E2E 均通过。
5. context 响应头、固定 TTL 和日志脱敏经代码/部署配置检查通过。
6. `npm run lint`、`npm test`、`npm run build`、`npm run test:e2e` 全部通过。
7. 模板模式在未设置 `DEEPSEEK_API_KEY` 时仍完成搜索、发现、打开和收藏。

P0 发布后，杨思涵负责 DeepSeek Adapter 与资源控制：5 秒超时、结构化校验、模板降级、缓存、分布式身份限流、全局并发、日预算、熔断与日志审计。佟雨泽负责展示模型/模板来源，并补充模型关闭、超时、预算耗尽时不阻断打开和收藏的 E2E。P1 未满足全部资源控制门槛前，Adapter 必须保持默认关闭。
