# 2026-08-26 最终方案：三层资源发现

## 1. 文档状态与最终决策

本文是 2026-08-26 的唯一实施规格。此前关于 AI「带我偏离一点」、三层发现体系、DeepSeek 和首次登录画像的草案均已被本文覆盖；开发、测试和验收均以本文为准。

产品将资源发现拆为三个不可替代的能力：

| 能力 | 用户问题 | 输入 | 输出 | 不得做的事 |
| --- | --- | --- | --- | --- |
| 搜索筛选 | 在明确范围内找资源 | 关键词、主题和硬筛选 | 满足全部硬条件的目录结果 | 按画像扩展或排除结果。 |
| 阅读偏好 | 哪些合格资源更贴近我 | 用户明确选择的标签和探索幅度 | 普通搜索和发现推荐中的可解释软排序 | 改变硬筛选集合或使用人口资料。 |
| 带我偏离一点 | 从当前资源值得走向哪里 | 当前资源、方向、已展示目标、可选硬约束 | 一条目录内、有关系解释的跳转 | 从互联网或模型生成候选，自动打断浏览。 |

优先级固定为：**硬筛选 > 资源可用性与公开性 > 关系图合法性 > 画像排序 > DeepSeek 叙述**。后层只能对前层候选排序或改写文案，不能扩大候选集合。

### 1.1 交付边界

| 优先级 | 范围 | 发布条件 |
| --- | --- | --- |
| P0，必须完成 | 资源语言与多值筛选、可分享 URL、画像表/RLS/问卷、显式个性化搜索排序、关系图发现 API 和模板叙述 | 匿名用户可筛选并得到目录内推荐；登录用户可管理偏好并选择个性化排序；无模型配置时全流程可用。 |
| P1，P0 后合入 | 画像参与发现排序、受约束的筛选来源上下文、具备资源控制的 DeepSeek Adapter | P0 测试通过，关系数据满足覆盖阈值，Preview 验证模型降级与限流。 |
| P2，不在当天发布范围 | 反馈学习、持久化模型文案、自动推断标签、向量检索 | 需真实数据、隐私审查和独立方案。 |

产品决策：首次登录后的核心偏好问卷是进入个性化能力的必经步骤，但不阻塞公共目录、资源详情、收藏或个人书架。未完成时，搜索和发现均回退到目录策展；用户可正常使用既有书架，并从其中继续完成“首次登录偏好引导”。“可关闭”仅指关闭当前引导提示，不代表已经获得个性化能力。

### 1.2 非目标

- 不做自由文本问答、聊天或互联网书目检索。
- 不持久化匿名浏览路径、推荐历史或模型输入。短期、加密的筛选来源上下文仅用于当前详情页的受约束偏离，见第 4.4 节。
- 不采集性别、年龄段、职业等人口资料。它们不驱动当前功能，却增加隐私和未成年人处理成本。
- 不让客户端提交目标资源、模型提示词、画像字段或服务端模型配置。

## 2. 用户体验

### 2.1 搜索与筛选

搜索框只接受关键词，匹配标题、作者和摘要。结构化条件由独立控件表达：

| 条件 | URL 重复键 | 语义 |
| --- | --- | --- |
| 主题 | `tag` | 一个受控标签 slug；与其他条件为 AND。 |
| 内容语言 | `language` | 可重复，如 `language=zh&language=en`；同字段多选为 OR。 |
| 出版时间 | `yearFrom`、`yearTo` | 闭区间；指定区间时未知年份不匹配。 |
| 资源类型 | `type` | 可重复；同字段多选为 OR。 |
| 可读状态 | `availability` | 可重复；同字段多选为 OR。 |

示例：

```text
/search?q=design&language=en&yearFrom=2000&yearTo=2026&type=book&availability=online
```

页面展示已生效条件的可删除 chips 和“清除全部”。删除一个 chip 仅移除相应值；清除全部保留关键词 `q`，移除所有结构化筛选。服务端每次依据 URL 重新查询，浏览器不得对已加载结果做二次伪筛选。

搜索排序有一个显式、可分享的 `sort` 参数：`sort=catalog`（默认）或 `sort=personalized`。用户主动选中“与你相关”后才写入后者。所有硬筛选先在数据库中完成；只有 `sort=personalized` 且请求携带有效 Bearer token、用户已完成偏好问卷时，服务端才对**完整合格候选集**计算亲和度并排序，再执行分页或 `limit`。匿名、token 无效、未完成问卷或空标签一律回退目录排序，响应清楚标记本次实际来源，绝不在浏览器对当前页结果重新排序。

### 2.2 首次登录偏好引导

登录成功或用户主动打开“阅读偏好”时，客户端请求 `GET /api/reader-profile`。未完成时显示可关闭的引导，不强制跳转。用户进入 `/onboarding` 后完成两步表单：

1. 必填：选择 3-8 个现有目录标签，选择探索幅度 `gentle`、`balanced` 或 `bold`，并同意“用于个性化推荐”。
2. 可选：最多三本喜欢的书及作者，仅供用户自己回顾和编辑，不参与 P0/P1 推荐或模型输入。

填写完成后，用户可在个人书架中重新编辑或清空偏好。清空只删除阅读偏好及喜爱书目，不删除 Auth 账号、`profiles` 或收藏。

### 2.3 带我偏离一点

入口位于资源详情页的收藏操作附近。默认方向为“意外连接”；用户可改选“延展主题”“换个观点”或“回到背景”。点击后只展示一张推荐卡：目标资源、实际关系标签、人工关系解释、引导文案、推荐来源，以及打开、再偏一次、收藏三个动作。

“再偏一次”只排除当前浏览器标签页已经展示过的目标，最多 20 个 UUID；页面卸载后不保存。候选耗尽返回正常空态，不用随机资源替代。

从搜索结果进入详情时，页面展示两个明确选项：

- “自由偏离”：仅遵守公开目录和关系图。
- “在当前筛选内偏离”：仅当详情 URL 携带有效 `discoveryContext` 时可选；无候选时返回“当前筛选范围内没有另一条路径”，用户自行改为自由偏离。

## 3. 数据设计

### 3.1 资源筛选数据

在新 migration 中扩展 `public.resources`，不修改既有 foundation migration：

```sql
alter table public.resources
  add column languages text[] not null default array['other']::text[]
  check (
    cardinality(languages) >= 1
    and languages <@ array['zh', 'en', 'other']::text[]
  );

create index if not exists resources_published_year_idx
  on public.resources (published_year);
create index if not exists resources_languages_idx
  on public.resources using gin (languages);
```

`languages` 表示资源本身可阅读的语言，不由页面标题或中文摘要推断。种子必须逐条标注；无法确认则标记 `other`。`published_year`、`type`、`availability` 复用现有字段和枚举。

目录搜索使用两个新函数名，而不是改变现有 `search_resource_catalog(text, text, text, integer)` 的输入签名：

- `search_resource_catalog_v2`：公开目录排序，授予 `anon` 与 `authenticated`。
- `search_resource_catalog_personalized_v2`：仅授予 `authenticated`；函数从 `auth.uid()` 读取已完成的偏好标签，绝不接受 `user_id` 或标签 ID 参数。

两者共用如下硬筛选参数和返回列；个性化函数仅在完整合格集合上额外按第 5.3 节的亲和度排序。`p_limit` 在排序之后应用，确保不发生“只排序当前页”的错误。

```text
p_q text | null
p_tag text | null
p_year_from integer | null
p_year_to integer | null
p_languages text[] | null
p_types text[] | null
p_availabilities text[] | null
p_limit integer
```

字段之间为 AND，同字段数组为 OR。`p_languages` 非空时，资源 `languages` 必须与其有交集。响应必须包含 `published_year` 和 `languages`，使页面可核实筛选结果。

迁移顺序是强制要求：先执行旧目录 migration，再由 `202608260003_create_resource_catalog_v2.sql` 使用 `DROP FUNCTION IF EXISTS public.search_resource_catalog(text, text, text, integer)` 删除旧 RPC，随后创建两个 `*_v2` 函数并只为各自目标角色执行 `GRANT EXECUTE`。API 与 ResourceCatalogModule 在同一版本中切换到 v2；本项目没有外部 RPC 客户端，因此不保留兼容窗口。迁移测试必须覆盖数据库已存在和不存在旧函数两种情况，并验证函数目录中没有同名旧重载或遗留 execute grant。

### 3.2 阅读偏好数据与权限

新增三个表，均开启 RLS，且不授予 `anon` 读取权限。

| 表 | 关键字段 | 约束 |
| --- | --- | --- |
| `reader_profiles` | `user_id` PK、`exploration_level`、`onboarding_completed_at`、`consent_at`、`updated_at` | `user_id` 外键指向 `auth.users`；探索幅度是受控枚举。 |
| `reader_profile_tags` | `user_id`、`tag_id`、`weight`、`source` | 联合主键；`tag_id` 外键指向 `tags`；P0 仅 `weight=1`、`source='selected'`。 |
| `reader_profile_favorite_books` | `id`、`user_id`、`title`、`author`、`created_at` | 标题 1-120 字，作者最多 80 字，每用户最多 3 条。 |

三张表仅允许 `authenticated` 读取自己的行，RLS 的 select 策略以 `auth.uid() = user_id` 为条件。禁止对 `anon` 和 `authenticated` 授予表级 insert、update、delete；用户不能经 REST 表 API 绕过问卷校验写入 `weight`、`source` 或不完整画像。`reader_profiles` 使用已有 `set_updated_at()` 触发器。普通用户请求使用带 Bearer token 的 Supabase 客户端；service role 不参与普通用户请求。

完整问卷写入只能经 `replace_reader_profile` RPC 完成，清空只能经 `clear_reader_profile` RPC 完成；二者都是 `SECURITY DEFINER` 函数，固定 `search_path = public, pg_temp`，并在入口要求 `auth.uid() is not null`。函数不接受 `userId` 参数，撤销 `PUBLIC` execute 后只授予 `authenticated` 执行权限。`replace_reader_profile` 在单一事务中校验同意项、3-8 个不重复且存在的标签 UUID、最多三本喜爱书目，更新 profile、替换标签和喜爱书目、设置完成与同意时间。`clear_reader_profile` 在同一事务中删除当前用户的三类画像记录。所有函数引用用户行时都使用 `auth.uid()`，不信任调用方身份字段。

### 3.3 关系图数据

`resource_relations` 是唯一的推荐候选事实来源。它是有向图，关系类型、人工解释和强度由策展维护：

| 方向 | 首选关系类型 | `surprise` 无候选时的回退 |
| --- | --- | --- |
| `extend` | `same_theme` | 无回退。 |
| `challenge` | `contrasting_view` | 无回退。 |
| `context` | `historical_context` | 无回退。 |
| `surprise` | `unexpected_bridge` | `contrasting_view`，再 `historical_context`，再 `same_theme`。 |

目录数据不随 schema migration 发布。关系补全和语言标注放在可重复执行的 seed 或数据 patch 中，以资源 slug 和 `(source, target, relation_type)` 为幂等键。P0 所有可展示资源至少有一条有效出向关系；首页精选和发现入口资源至少有 3 条、覆盖至少两个关系类型。画像排序上线前，每个热门起点须有 3-5 条标签分布不同的候选，并至少一条 `unexpected_bridge`。

## 4. 契约设计

### 4.1 共享类型

```ts
type ResourceLanguage = "zh" | "en" | "other";
type DiscoveryMode = "extend" | "challenge" | "context" | "surprise";
type ExplorationLevel = "gentle" | "balanced" | "bold";

type SearchSort = "catalog" | "personalized";

type SearchResourcesQuery = {
  q?: string;
  tag?: string;
  languages?: ResourceLanguage[];
  yearFrom?: number;
  yearTo?: number;
  types?: ResourceType[];
  availabilities?: Availability[];
  sort?: SearchSort;
  limit?: number;
};
```

`Resource` 和 `ResourceListItem` 都增加 `languages`；`ResourceListItem` 同时增加 `publishedYear`。`SearchResourcesData.appliedFilters` 回传规范化后的全部筛选字段，并新增 `personalization: "profile" | "catalog"` 和 `appliedSort: SearchSort`。当请求 `sort=personalized` 但无可用画像时，`appliedSort` 必须为 `catalog`，而非回显未生效的请求值。

### 4.2 `GET /api/resources`

Route Handler 必须使用 `request.nextUrl.searchParams.getAll()` 读取 `language`、`type`、`availability`，不能使用 `Object.fromEntries()`，后者会丢失重复键。先将 URL 键映射为共享类型的数组字段，再交给严格 Zod schema。它可选读取 Bearer token；只有 `sort=personalized` 时才将认证身份传给 ResourceCatalogModule 读取已完成画像，认证失败不使公开搜索失败。

无效枚举、未知 query key、超过上限、非法 UUID、`yearFrom > yearTo` 均返回 `400 VALIDATION_ERROR`。目录数据库不可用返回 `503 SUPABASE_UNAVAILABLE`。

`CatalogFilterModule` 是 URL 参数的唯一拥有者：

```ts
parseSearchFilters(searchParams): SearchResourcesQuery
serializeSearchFilters(filters): string
removeSearchFilter(filters, filter): SearchResourcesQuery
clearSearchFilters(filters): SearchResourcesQuery
```

页面和组件不得自行拼接 query string。`clearSearchFilters` 保留 `q` 和 `sort`；排序切换单独修改 `sort`，不重置硬筛选。

### 4.3 `GET`、`PUT`、`DELETE /api/reader-profile`

三个接口都要求 `Authorization: Bearer <access token>`；没有或失效 token 返回 `401 UNAUTHORIZED`。接口不接收 `userId`，服务端从 token 派生身份。

```ts
type ReadingProfileData =
  | { status: "incomplete"; preferences: null }
  | { status: "complete"; preferences: {
      explorationLevel: ExplorationLevel;
      interestTags: Tag[];
      favoriteBooks: Array<{ id: string; title: string; author: string | null }>;
      onboardingCompletedAt: string;
    } };

type ReplaceReaderProfileRequest = {
  interestTagIds: string[]; // 3-8 个互异 UUID
  explorationLevel: ExplorationLevel;
  favoriteBooks?: Array<{ title: string; author?: string }>; // 最多 3 项
  consent: true;
};
```

`PUT` 调用 RPC 原子替换全部画像。`DELETE` 清空三张偏好表的当前用户数据并返回 `200`；之后 discovery 自动回退到目录策展排序。

### 4.4 筛选来源上下文

`discoveryContext` 是一个服务器签发的 AES-256-GCM 加密认证 token，5 分钟过期。加密既保证完整性，也避免筛选内容出现在浏览器历史、Referer 和应用访问日志中。其解密后的 payload 只包含版本、资源 slug、规范化硬筛选、签发和过期时间：

```ts
type DiscoveryContextPayload = {
  version: 1;
  originSlug: string;
  filters: Pick<SearchResourcesQuery,
    "languages" | "yearFrom" | "yearTo" | "types" | "availabilities" | "tag">;
  issuedAt: number;
  expiresAt: number;
};
```

它不包含关键词、用户 ID、画像、邮箱、访问 token 或收藏信息。搜索页面为每个资源卡在服务端渲染时，以该资源 slug 和当前规范化硬筛选签发 token，并作为可选详情 URL 参数传递；没有结构化筛选时不签发。详情页只在用户选择“在当前筛选内偏离”时把该 token 发送给 discoveries API，因此携带 token 本身不会约束普通详情浏览或自由偏离。

服务端解密、验证认证标签、检查过期时间并确认 `originSlug` 与当前起点一致；失效或篡改 token 返回 `400 INVALID_DISCOVERY_CONTEXT`，前端保留已得到的详情内容并提示用户改为自由偏离。密钥仅使用服务端 `DISCOVERY_CONTEXT_ENCRYPTION_KEY`，为 32 字节随机值并与其他密钥轮换策略独立。

所有包含 `discoveryContext` 的页面和 API 响应设置 `Cache-Control: private, no-store` 与 `Referrer-Policy: same-origin`；应用、反向代理、CDN、错误追踪和分析日志必须在记录前删除该 query key 和请求体中的 context 字段。日志只可记录 `context=present|invalid|expired`，不得记录密文、解密字段、完整 URL 或 Referer。token 不写数据库、不写 cookie、不进入客户端埋点，并在 5 分钟到期后不可恢复。

### 4.5 `POST /api/discoveries`

```ts
type DiscoverRequest = {
  originResourceId: string;
  mode?: DiscoveryMode; // 默认 surprise
  excludeResourceIds?: string[]; // 最多 20 个不重复 UUID
  discoveryContext?: string;
};

type DiscoverResponse = {
  originResourceId: string;
  selectedMode: DiscoveryMode;
  usedRelationType: RelationType | null;
  constrainedBySourceFilters: boolean;
  personalization: "profile" | "catalog";
  recommendation: {
    resource: ResourceListItem;
    relationExplanation: string;
    narration: string;
    narrationSource: "template" | "deepseek";
  } | null;
};
```

推荐公开可读。Route 可选读取 Authorization token：无 token、失效 token、未完成画像或无兴趣标签时，都使用 `catalog` 排序而不报认证错误；只有受保护画像接口要求登录。非法 body 返回 `400 VALIDATION_ERROR`，起点不存在返回 `404 RESOURCE_NOT_FOUND`，目录不可读返回 `503 SUPABASE_UNAVAILABLE`。

## 5. 推荐算法

`DiscoveryModule.discover(input)` 是业务边界。Route Handler 和页面只知道输入及 `DiscoverResponse`，不理解 SQL、回退、画像计算、模型调用、超时和降级。内部模块包括关系读取 Adapter、纯排序函数、可选画像读取器和叙述 Adapter。

### 5.1 候选筛选

1. 读取起点和其出向 `resource_relations`，联接目标资源、目标标签和人工解释。
2. 排除自身、`excludeResourceIds`、不存在或不公开展示的目标。
3. 请求带有效 `discoveryContext` 时，对目标应用其中的语言、年份、类型、可读状态和主题约束；`tag` 与资源标签同样为 AND 条件。
4. 按请求模式取首选关系类型；仅 `surprise` 按第 3.3 节顺序扩大到下一类。响应始终回传实际 `usedRelationType`。
5. 候选为空时返回 `recommendation: null` 和 HTTP 200，不发送模型请求。

### 5.2 发现推荐的确定性排序

关系强度是主排序键，画像只在同一强度分组内排序；强度不同的候选不得因偏好分数颠倒。

```text
weightedDiceAffinity =
  2 * sum(weight(tag) for tag in target ∩ interests)
  / (sum(weight(tag) for tag in target) + sum(weight(tag) for tag in interests))
```

P0 所有兴趣标签权重为 `1`。任一集合为空时 weighted Dice affinity 为 `null`，使用目录排序。每个 strength 分组内：

| 探索幅度 | 画像排序键，升序 | 说明 |
| --- | --- | --- |
| `gentle` | `-weightedDiceAffinity` | 亲和度越高越优先。 |
| `balanced` | `abs(weightedDiceAffinity - 0.5)` | 最接近中等亲和度者优先。 |
| `bold` | `abs(weightedDiceAffinity - 0.2)` | 最接近低但非零亲和度者优先。 |

`bold` 不改变用户选择的关系类型：显式选择 `extend`、`challenge`、`context` 时仍在相应候选中排序；只有 `surprise` 的候选或回退规则决定关系类型。若 `bold` 分组没有正 weighted Dice affinity 候选，允许该值为 0，仍必须有人工关系解释。

最终比较器：`strength desc`、当前探索幅度排序键 `asc`、`relation.id asc`。匿名、未完成问卷和缺少标签时为 `strength desc`、`relation.id asc`。全部计算是纯函数并具有固定样例测试。

### 5.3 普通搜索的个性化排序

普通搜索先由 `search_resource_catalog_personalized_v2` 应用全部硬筛选，再仅在合格集合内计算每项资源与已完成画像的 `weightedDiceAffinity`。其固定比较器为：`weightedDiceAffinity desc`、`is_featured desc`、`created_at desc`、`id desc`。它不使用探索幅度，后者仅描述用户愿意在“偏离一点”中走多远。

当用户请求 `sort=personalized`，但 token 无效、画像未完成或兴趣标签为空，ResourceCatalogModule 不调用个性化 RPC，改调用公开 `search_resource_catalog_v2`，并返回 `appliedSort: "catalog"`、`personalization: "catalog"`。这样共享 URL 仍可打开，且不会泄露“是否存在某个用户画像”。

## 6. DeepSeek 叙述与降级

DeepSeek 不参与候选获取和排序。`DeepSeekNarrationAdapter` 只在目标确定后调用，输入为：

```ts
{
  origin: { title: string; summary: string; tags: string[] };
  target: { title: string; summary: string; tags: string[] };
  relationType: RelationType;
  relationExplanation: string;
  readingLens?: {
    interestTags: string[];
    explorationLevel: ExplorationLevel;
    currentMode: DiscoveryMode;
  };
}
```

禁止传入用户 ID、邮箱、访问令牌、喜爱书目原文，以及目录外用户输入。环境变量为服务端专用 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`；Provider 接口参数以实现当日的官方文档为准，不进入浏览器包或共享类型。

模型输出只接受 `{ narration: string }`，Zod 校验为 20-90 个汉字。提示词要求只描述“从什么问题走向什么问题”，不添加书目、作者、链接、可读状态或未经提供的事实。服务端用 `AbortSignal.timeout(5000)` 限时并限制请求大小。未配置、超时、网络错误、非法 JSON、长度非法、含 URL 或额外书目时，直接使用 `relationExplanation`，返回 `narrationSource: "template"` 和 HTTP 200。

Adapter 启用前必须接入共享的服务端限流与预算模块：匿名请求按经过可信代理规范化的 IP 加起点资源限流（每分钟 10 次）；登录请求按 `userId` 加起点资源限流（每分钟 20 次）；每个身份每日最多 100 次模型尝试。再额外设置全局并发上限 10、每日 Provider 预算上限和熔断器。所有阈值均以服务器环境变量配置，并在部署环境中使用原子计数存储，不依赖单进程内存。

在调用 Provider 前，按 `originResourceId`、`targetResourceId`、`relation.id`、`mode`、`personalization` 和阅读镜头版本计算不含个人信息的缓存键。已校验 narration 可复用 15 分钟；模板结果可复用 60 秒以减少失败风暴。命中缓存不消耗配额。触发身份限流、并发上限、日预算或熔断器时，Discovery API 不返回 429，也不阻塞推荐：跳过模型调用、返回人工模板，并在内部指标记录 `modelSkippedReason`。独立的 API 边缘滥用限制仅按 IP 和请求体字节数执行，超额时在调用任何目录或模型依赖前返回 `429 RATE_LIMITED`；超额大小请求本身返回 `400 VALIDATION_ERROR`。

人工 `relationExplanation` 是唯一事实解释；模型文案是非事实性的阅读引导。P1 发布时 Adapter 默认关闭，先以模板模式部署和验收。

- 筛选：语言交集、类型/可读状态 OR、字段 AND、年份闭区间、重复 URL 键、未知参数和倒置年份。

### 9.2 发布验收故事

1. 匿名用户搜索 `design`，选择英文、2000-2026 年、图书和在线资源；结果满足全部条件，复制 URL 后结果一致。

## 10. 发布门禁与后续决策

上线前必须完成资源语言覆盖审计；所有可展示资源至少有一条有效出向关系；热门起点满足候选数量阈值；旧搜索 RPC 已删除且 v2 迁移验证通过；画像表 API 直写被拒绝；P0 自动化测试、lint、build 和 Preview 验收通过；模板模式完整可用。

DeepSeek 只有在配置隔离、请求长度限制、5 秒超时、结构化校验、模板降级、分布式身份限流、全局并发、Provider 日预算、熔断、缓存和无个人数据/context token 日志审查全部通过后才开启。反馈学习、模型文案持久化或推断标签须另起方案，包含数据保留期限、撤回机制、评估指标和隐私审查，不能作为本次实现的隐含扩展。
