## 方案实现完整性审查

### 审查目标

- 类型：当前 `HEAD` 的全量规格核验，不限近期提交。
- 依据：`docs/ai-discovery/方案设计.md`。
- 范围：前端工作流、API/服务、Supabase migration 与 seed、权限和测试发布门禁。

### 审查输入证据

- 自动化检查：`npm run lint`、`npm test`（15 个文件、76 项）和 `npm run build` 均通过。
- 未执行真实 Supabase migration/RLS 环境或 Preview 人工验收；现有数据库测试仅检查 SQL 文本。

### 问题清单

#### 阻塞“完全实现”

1. P1 的 DeepSeek Adapter 与资源控制尚未实现。`discover()` 只返回人工 `relationExplanation`，并固定 `narrationSource: "template"`；仓库没有方案列出的 `lib/services/deepseek-narration.ts` 和 `lib/services/request-limits.ts`。因此 5 秒超时、输出校验、缓存、分布式限流、并发、预算和熔断均不存在。位置：`lib/services/discovery.ts:225-230`、`docs/ai-discovery/方案设计.md:304-330`、`:343-344`。

2. 关系数据未达到 P0 覆盖门槛。公开目录 seed 有 20 条资源，但关系 seed 的出向起点只有 `the-creative-act`、`the-image-of-the-city`、`the-library-of-babel`；其余至少 17 个资源的发现操作只能得到空态。方案要求每个可展示资源至少一条有效出向关系，并要求提供覆盖审计。位置：`supabase/seed/resources-v1.sql:29-165`、`:214-240`、`supabase/seed/resources-v2-relations.sql:19-82`、`docs/ai-discovery/方案设计.md:147`、`:434`。

3. v2 搜索 RPC migration 不满足“旧函数不存在时也可验证”的规格。migration 对旧函数使用无条件 `revoke` 与 `drop`，旧函数不存在或重复运行时会失败；测试还显式禁止 `IF EXISTS`。方案要求 `DROP FUNCTION IF EXISTS`，且 migration 测试覆盖旧函数存在和不存在两种情形。位置：`supabase/migrations/202608260003_create_resource_catalog_v2.sql:1-3`、`tests/database/resource-catalog-v2-migration.test.ts:23-32`、`docs/ai-discovery/方案设计.md:120`。

#### 发布门禁未满足

1. 新发现路径与权限边界没有可执行验证。`reader-profile-migration` 测试只读取 SQL 字符串，未以两个用户验证 RLS 隔离、RPC 原子替换和 REST 表 API 直写拒绝；`POST /api/discoveries` 与新的 `discover()` 也没有 route/service 测试。位置：`tests/database/reader-profile-migration.test.ts:1-87`、`app/api/discoveries/route.ts:5-41`、`lib/services/discovery.ts:164-231`、`docs/ai-discovery/方案设计.md:373`、`:416-421`。

2. 没有 E2E 运行器、脚本或浏览器冒烟用例。当前只有 Vitest；未覆盖匿名筛选到自由偏离、登录完成问卷后书架可用、两用户排序差异和模型降级等验收故事。位置：`package.json:5-10`、`docs/ai-discovery/方案设计.md:406`、`:421`。

#### 前端呈现差距

1. 推荐卡没有显示 `narrationSource`。契约已返回 `template | deepseek`，但面板只展示关系、画像排序和来源筛选状态；方案要求卡片展示推荐来源，模型启用后用户无法区分人工模板与模型叙述。位置：`lib/types/resources.ts:161-175`、`components/resources/discovery-panel.tsx:101-102`、`docs/ai-discovery/方案设计.md:69`。
